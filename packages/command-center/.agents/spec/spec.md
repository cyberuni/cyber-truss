# Command Center

The application through which the Council observes projects, coordinates work, inspects
findings and evidence, and answers requests — without taking over the session the Council
is working in.

Command Center owns the **application shell, composed views, decisions, and navigation**.
It owns none of the models it renders: Truss artifact relationships, Cyberfleet actor
ownership, and SDD workflow state are distinct authoritative stores, joined through stable
references. The application keeps no copy of them.

Initiative: [cyber-truss#5](https://github.com/cyberuni/cyber-truss/issues/5).

## Placement map

**Strategy: `capability-first`.** Top-level folders name what the application does. Nodes
are `<capability>/<unit>` and never three deep; a sub-grouping inside a capability is a
`concept:` tag, not a folder.

| A concept of this kind | lives in |
| --- | --- |
| A rule, model, or boundary — the *why* | `design/` |
| An architecture decision, append-only | `design/decisions/` |
| A flow composing several capabilities | `workflows/` |
| Hosting a domain integration: load, refresh, act, unload, version | `integration/` |
| Rendering composed state from the authoritative stores | `views/` |
| Presenting a pending decision and returning an answer | `decisions/` |
| Application lifecycle, navigation, portable entry, restart | `shell/` |
| Build, packaging, release, dependencies | `tooling/` |
| Durable gate provenance | `ledger/` |

### Tie-breaks

| Contested concept | Home | Why |
| --- | --- | --- |
| Obtaining and holding a provider | `integration/provider-binding` | Discovery, the handshake, per-contract compatibility, snapshot freshness, release. |
| What travels over a binding | `integration/provider-exchange` | Following a reference, dispatching an action, and the guarantee an unknown outcome is never re-sent. |
| Unavailable / stale integration state | `integration/provider-binding` | A property of holding a provider, surfaced by `views/`; the truth lives with the host. |
| An in-flight action when its provider goes away | `integration/provider-exchange` | The outcome is a property of the action, not of the release — splitting it would put one decision in two nodes. |
