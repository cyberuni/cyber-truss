This is the [pagination bug](/cyber-truss/examples/software-bug-fix/) moved into a
component library. What changes is who reads the docs. In an application the help page
describes behaviour to users. In a library the docs describe an API to developers, who
write code against it.

## The system

A component library that publishes a `Pagination` component. The consumer passes the page
count as a `totalPages` prop.

| Artifact-set | Holds |
| --- | --- |
| `{spec}` | Intent and criteria for the component's behaviour |
| `{code, test}` | The component and its tests, one unit of change |
| `{API docs}` | The reference page: props, types, defaults, and a usage example |
| `{mockups}` | The design-system mockups of the component |

The usage example on the reference page computes the page count for the consumer:

```tsx
<Pagination totalPages={Math.floor(items.length / pageSize) + 1} />
```

Connections:

- `{spec}` to `{code, test}`
- `{spec}` to `{API docs}`
- `{spec}` to `{mockups}`
- `{mockups}` to `{code, test}`
- `{API docs}` to `{code, test}`

The last connection is the one the application example did not need. The spec states
behaviour and does not name props. A spec that says *the consumer supplies the page count*
is satisfied by `totalPages`, by `pageCount`, or by a function. The reference page must
state which one, with its type and default, so it cannot be checked against the spec
alone. It can only be checked against the code.

The spec's criteria say the indicator shows the current page and the total, and the
documented way to compute the total produces no empty page. The usage example breaks that
criterion on an exact multiple, and nothing has noticed.

## Workflows

| Workflow | Inputs | Outputs | Shape |
| --- | --- | --- | --- |
| Component delivery | `{spec}` | `{code, test}` | one link |
| Docs update | `{spec}` | `{API docs}` | one link |
| API contract | `{API docs}` | `{code, test}` | one link |
| Design update | `{spec}` | `{mockups}` | one link |
| Design implementation | `{mockups}` | `{code, test}` | one link |

API contract reads the reference page and writes the code. The published API is a contract
with consumers, so the code must accept what the page documents. A team could declare the
opposite, an API reference workflow that reads the code and writes the page. That workflow
documents whatever shipped, and on this change it would rewrite the page to the new props
and publish the break. The
[declaration decides](/cyber-truss/model/workflow/#direction-lives-in-the-workflow).

## The change

A consumer reports an empty last page. The same intent reaches the library by two
different routes, one per variant.

## Variant A: the fix changes the API

A developer decides consumers should not compute the page count at all. They replace
`totalPages` with `totalItems` and `pageSize`, compute the count inside the component,
round up, and commit. The diff touches the code and tests only. Every consumer passing
`totalPages` breaks on upgrade.

### Expected run

1. **Lift.** The change touches `{code, test}`.
2. **Identify.** Three workflows output `{code, test}`: component delivery, API contract,
   and design implementation.
3. **Distill.** Distillation
   [reads back](/cyber-truss/model/canonical-execution/#distillation-reads-backward) along
   all three. `{spec}` holds the change's rule, since the documented way to compute the total
   must produce no empty page. `{mockups}` shows the indicator unchanged. `{API docs}`
   documents a `totalPages` prop the code no longer accepts, and a usage example that rounds
   down. Intent: *every page shows at least one item.* The new props are how the developer
   expressed it.
4. **Derive criteria.** An exact multiple produces no empty page, and the documented way to
   reach a page count rounds up.
5. **Select.** `{spec}` and `{mockups}` already hold the criteria, so component delivery and
   design implementation do not run. `{API docs}` to `{code, test}` is strained, because
   the page documents a prop the code no longer accepts. API contract spans it and writes
   the code, the end that has to change under its declaration, so it runs. The usage
   example also contradicts the second criterion. The page is API contract's input, though,
   and docs update, the one workflow that writes it, spans `{spec}` to `{API docs}`. That
   connection is not on the changed set, so no step selects docs update.
6. **Replay.** API contract translates the intent into a Request at `{API docs}`. It cannot
   change the page, so it derives code that accepts `totalPages` as documented.
7. **Compare.** The developer's change meets the first criterion and breaks every consumer
   to do it. The architect lens reports *change course*. The replay keeps the contract and
   has a hole: the documented way to compute the page count still rounds down, so the
   second criterion is unmet. The comparison reports the hole, and nothing carries it to
   docs update.
8. **Propagate.** The replay restores `{API docs}` to `{code, test}`. Nothing else it wrote
   is strained.

Without the `{API docs}` to `{code, test}` connection, step 5 finds no strain at all. The
run selects nothing, the reference page documents a removed prop, and the break reaches
consumers first.

### Settled state

None. The run ends with the comparison's hole open.

- `{spec}` is unchanged.
- `{code, test}` accepts `totalPages` as before.
- `{API docs}` still computes the page count by rounding down.
- `{mockups}` is unchanged.

### Status: Gap

The declaration keeps the break from shipping, which the earlier reading of this example
could not promise. The consumer's bug is still there. Distillation reads the defective
usage example and the criterion it contradicts, but selection checks only connections on
the changed set, and the one identified workflow that reads the page cannot write it. The
contradiction is seen and not routed. The
[fiction example](/cyber-truss/examples/fiction-plot-twist/) finds the same gap with
criteria no selected workflow can hold.

Two further points stay open.

- **Where the connection sits.** `{spec}` connects to `{code, test}` at behaviour.
  `{API docs}` connects to it at the exported props and their types, a rung below. The
  model has not said [how levels are identified](/cyber-truss/model/specification/#specifications-exist-at-every-level)
  across artifact types, and this connection cannot be evaluated until it does.
- **What distillation keeps.** Step 3 reads the new props as expression. A distiller could
  read *the component owns the page count* as part of the intent. Its criteria would then
  say consumers never compute the page count, while `{API docs}` documents that they do.
  The page is an input of every workflow that writes the code, and no specification states
  the wider intent, so nothing can replace the documented prop. The two criteria reach
  `{code, test}` together and contradict each other, which is a
  [conflict](/cyber-truss/model/join/#conflict). The run stops for a recorded decision
  instead of shipping the break. See
  [Can distillation be made stable?](/cyber-truss/model/open-questions/#can-distillation-be-made-stable)

## Variant B: the fix lands in the docs

A technical writer corrects the usage example to round up. The diff touches the reference
page only.

### Expected run

1. **Lift.** The change touches `{API docs}`.
2. **Identify.** Docs update is the one workflow that outputs `{API docs}`.
3. **Distill.** The walk reaches `{spec}`, which holds the rule the correction implements.
   The intent is the same as in variant A.
4. **Derive criteria.** The same as variant A.
5. **Select.** `{spec}` holds the criteria, so docs update does not run. On the changed set,
   `{spec}` to `{API docs}` now holds, and `{API docs}` to `{code, test}` holds, because the
   props the page documents are the props the code accepts. Nothing is selected.
6. **Replay.** Nothing replays. The correction stands as made.

### Settled state

- `{spec}` is unchanged.
- `{code, test}` accepts `totalPages` as before.
- `{API docs}` computes the page count by rounding up.
- `{mockups}` is unchanged.

### Status: Holds

The correction lands where the defect lived, and the contract keeps a docs fix from pulling
in any code workflow. This is the state variant A should reach and does not. Until A's gap
closes, one intent entering at two points ends in two places, and the model does not yet
deliver [confluence](/cyber-truss/model/confluence/) on this pair.

## What it tests

- A connection between two implementations of one specification. `{API docs}` and
  `{code, test}` both implement `{spec}`, and the docs still need the code, because the
  spec leaves the API open. A connection between siblings cannot always be derived
  through their common parent.
- [Direction lives in the workflow](/cyber-truss/model/workflow/#direction-lives-in-the-workflow)
  on an edge where either side can be the specification. Declaring API contract rather
  than API reference is what keeps the break from shipping.
- [Distillation reads backward](/cyber-truss/model/canonical-execution/#distillation-reads-backward)
  against [selection](/cyber-truss/model/workflow/#how-workflows-are-selected). Variant A
  distills a contradiction in a set no selected workflow may write, and no selection step
  reaches the workflow that writes it.
- [Distillation carries the weight](/cyber-truss/model/canonical-execution/#distillation-carries-the-weight).
  The two variants are the test that section proposes: two expressions of one intent,
  which must distill to the same thing. A wider reading in variant A now surfaces as a
  conflict rather than a silent break.
- [Reading the comparison](/cyber-truss/model/canonical-execution/#reading-the-comparison)
  past the builder lens. The developer's change conforms, and the comparison rejects it on
  shape. The replay conforms to the contract, and the comparison finds its hole.
- Strain that predates the change. The docs example broke the spec long before either
  variant. Distillation reads it in variant A, and selection still does not act on it.
  Only variant B, or a cold [nonconformance](/cyber-truss/model/connections/#nonconformance)
  check, clears it.
- Versioning is left out. A breaking change obliges a major version and a migration note,
  which the [workflow catalog](/cyber-truss/model/workflows/) would treat as obligations
  rather than artifact-sets.
